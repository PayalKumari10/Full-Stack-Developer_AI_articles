As a Full Stack developer moving into AI, one of the first real problems you face is this. Large language models are smart, but they do not know your private data like PDFs, notes, or internal docs. If you want to build a chat system that answers questions from a PDF, you need a way to connect the model with your data.  
This is where RAG comes in. This article documents my learning step by step, exactly how I wanted to read it as a beginner.

---

## What is RAG in simple words

RAG stands for Retrieval Augmented Generation.  
It means we first retrieve relevant information from our own data and then give that information to the language model to generate an answer.

Instead of asking the model to guess, we help it by giving the right context.

Think of it like this.  
Before answering a question, the system quickly opens a book, finds the right page, and then explains the answer in its own words.

![](https://cdn.hashnode.com/res/hashnode/image/upload/v1769605800386/8e0b4bce-3086-408d-9589-f020cc4d598f.png align="center")

## 1\. Intro to RAG and LangChain

RAG is the idea.  
LangChain is the tool that helps us build it easily in Python.

LangChain connects documents, embeddings, vector databases, and language models into one flow. As developers, this feels similar to wiring controllers, services, and databases together.

## 2\. Defining the core problem in RAG systems

The core problem is simple.  
LLMs do not remember your PDFs.

If you upload a PDF today and ask a question tomorrow, the model has no idea what is inside that file unless you provide the content again.

So the problem becomes.  
How do we store document knowledge in a way that can be searched efficiently?

## 3\. Naive retrieval based solution approach

The basic RAG approach works like this.

1. Read the document
    
2. Break it into smaller pieces
    
3. Convert those pieces into vectors
    
4. Store them in a vector database
    
5. When a user asks a question, find the closest pieces
    
6. Send them to the language model
    

This improves accuracy because the model answers using real data instead of assumptions.

## 4\. RAG pipeline indexing workflow explained

Indexing means preparing your data for search.

The steps are.  
Load the PDF  
Split it into chunks  
Create embeddings  
Store them in a vector database

Indexing is done once. Querying happens many times later.

## 5\. RAG pipeline retrieval mechanism

When a user asks a question, the system does this.

The question is converted into a vector  
The vector database finds similar document chunks  
Those chunks are passed to the language model  
The model generates an answer using that context

This feels similar to searching rows using indexes in a database.

## 6\. Local vector database setup with Docker

There are many vector databases available like Pinecone, Weaviate, Chroma, PgVector, and Qdrant.

Qdrant is easy to set up locally, so it is great for learning.

### Docker Compose file

```yaml
services:
  vector-db:
    image: qdrant/qdrant
    ports:
      - 6333:6333
```

Run this and Qdrant will be available locally.

You can open the dashboard at  
[http://localhost:6333/dashboard](http://localhost:6333/dashboard)

## 7\. LangChain installation and setup

LangChain helps integrate language models into applications.

It is commonly used for  
Document analysis  
Chatbots  
Summarization  
Code analysis

For our use case, it acts as the glue between PDFs, embeddings, and the vector database.

## 8\. LangChain document loaders for PDF

LangChain provides document loaders to read files easily.

```python
from langchain_community.document_loaders import PyPDFLoader
from pathlib import Path

pdf_path = Path(__file__).parent / "Node.js_Action.pdf"
loader = PyPDFLoader(file_path=pdf_path)
docs = loader.load()
```

### Output

A list of document objects, each representing pages from the PDF.

### Explanation

Each page is converted into text so Python can process it further.

## 9\. Document chunking and splitting

Large documents are hard to search. So we split them into smaller chunks.

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=400,
)

chunks = text_splitter.split_documents(documents=docs)
```

### Output

A list of smaller text chunks.

### Explanation

Each chunk overlaps slightly so important context is not lost between sections.

## 10\. Vector store as retrievers

Now we convert text into embeddings and store them in Qdrant.

```python
from dotenv import load_dotenv
from langchain_openai import OpenAIEmbeddings
from langchain_qdrant import QdrantVectorStore

load_dotenv()

embedding_model = OpenAIEmbeddings(
    model="text-embedding-3-large"
)

vector_store = QdrantVectorStore.from_documents(
    documents=chunks,
    embedding=embedding_model,
    url="http://localhost:6333",
    collection_name="learning_rag"
)

print("Indexing of documents done successfully!")
```

### Output

```bash
Indexing of documents done successfully!
```

### Explanation

Each chunk is converted into a vector and stored in Qdrant.  
This allows fast similarity search later.

## 11\. LangChain powered RAG retrieval execution

At this point, your system is ready to answer questions.

When a query comes in, LangChain retrieves relevant chunks from Qdrant and sends them to the language model.  
The response is grounded in your PDF data, not guesses.
